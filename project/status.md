## בדיקות חוזרות בעבודה הנוכחית

- Deno 2.5.6: בדיקת טיפוסים ו-5/5 בדיקות קלט עברו.
- Node: תחביר `docs/app.js` ו-5/5 בדיקות פתיחת הדף עם תצורות Supabase, גיבוי וכתובות שגויות עברו.
- Python: בדיקת קומפילציה לשני כלי המעבר עברה.
- `supabase/tests/database.sql`: כל 13 בדיקות ה-assert עברו במסד הקיים בתוך transaction שבוטל. אומת `plpgsql.check_asserts=on`, ולא נותרו לקוח, בקשה, פריטים, העלאות או הודעות של `QA_SQL`.
- Chromium מול API מדומה: קישור חסר, קישור שגוי, תיקיית לקוח, פתיחת מסמך, RTL והיעדר שגיאות JavaScript עברו. הבדיקה אינה בדיקת ממשק מול השרת החי.
- שתי המיגרציות בחבילה תואמות לרשומות ההיסטוריה המרוחקת. Security Advisor: אפס אזהרות/שגיאות, 14 הודעות מידע צפויות על RLS ללא policies, כי הגישה מותרת לשרת בלבד.
- `live_api.py` לא הורץ מחדש: טוקן QA אינו זמין ולקוח `QA_MIGRATION` מושבת. 23 הקריאות המתוארות להלן הן ראיות מההרצה הקודמת בחבילה, ולא תוצאות חדשות.
- בדיקת טלפון אמיתי, השוואת הגיליון וסנכרון ההפרשים עדיין פתוחים.

## מה בוצע

- **מסד:** 13 טבלאות עסקיות ו-api_limits, עם סוגי נתונים, מפתחות זרים, אינדקסים, אילוצים ו-RLS. שתי המיגרציות ב-`supabase/migrations/` תואמות להיסטוריה המרוחקת.
- **נתונים:** הועתק מצב הגיליון הפעיל, לא רק seed: 60 לקוחות, 158 בקשות, 900 פריטים, 1,028 העלאות, 494 הודעות ו-1,241 רשומות יומן. הערות, אישורי משרד, זמנים ומזהי Drive נשמרו. 0 אי-התאמות בין ספירות קבצים לרישומי ההעלאות.
- **קישורים:** הטוקנים הקיימים נשמרו כ-SHA-256. הקישורים האישיים הישנים ממשיכים לעבוד. טוקנים וייצוא הגיליון לא נכנסו למאגר הציבורי.
- **שרת:** Edge Function בשם `nelio-api`, גרסה 0.6.0, עם hello/upload/markNa/unmarkNa/note. אין עוד צורך ב-Apps Script לפעולות דף הלקוח.
- **אחסון:** קבצים חדשים ב-bucket פרטי `nelio-documents`; קבצים ישנים נשארים ב-Drive. שום קובץ עסקי לא נמחק. שמירת קובץ עוברת הקצאה → אחסון → אישור, וניסיון חוזר אינו יוצר עותק נוסף.
- **דף:** `docs/config.js` מצביע ל-Supabase; מספר הגרסה 0.6.0; נוספה אזהרה על תוכן כפול בניסיון העלאה חדש. העיצוב נשמר.
- **הודעות:** אישור אחד לכל בקשה, simulated בדמו ו-queued אחרת, כמו לפני המעבר. לא נשלחו מיילים אמיתיים.
- **כלי עבודה:** בדיקות Deno, SQL ו-HTTP במאגר; ממיר ייצוא הגיליון; תיעוד פריסה, מיפוי ודרך חזרה מבוקרת; CI לבדיקות; workflow לפריסת Supabase. פריסת Apps Script הוסבה לידנית בלבד.

## בדיקות קודמות שתועדו בחבילה

- Type checking של Edge Function, 5 קבוצות בדיקות קלט Deno ותחביר JavaScript.
- בדיקות SQL שחוזרות לאחור בסיום: מצבים, אישור פעם אחת, שמירת complete, שיוך מסמכים, מניעת אישור קובץ שלא קיים, ביטול והחלפת טוקן והרשאות.
- 23 קריאות לשרת החי, כולל Storage אמיתי, ניסיון חוזר, תוכן כפול ושתי העלאות במקביל עם אותו מפתח. מניין הקבצים עלה פעם אחת בלבד.
- גישה ישירה לטבלת clients נדחתה ב-HTTP 401. ניסיון לפתוח קובץ דרך כתובת Storage ציבורית נדחה. אין הרשאת קריאה לטבלאות או הפעלת RPC ל-anon/authenticated.
- Security Advisor: ללא אזהרות/שגיאות. 14 הודעות מידע על RLS ללא policies הן מכוונות: השרת הוא היחיד שניגש למסד.
- לקוח הבדיקה הטכני `QA_MIGRATION` כולל 3 קובצי PNG המסומנים לדוגמה ואישור אחד. אינו חלק מ-60 הלקוחות; הושבת אחרי הבדיקות ואינו יכול להשתמש ב-API.
- Chromium מקומי לא עלה בגלל מגבלת socket בסביבת ההרצה; אין להסיק מכך על המוצר. בדיקת הדפדפן החי לא בוצעה משום שהפרסום נחסם; בדיקת טלפון אמיתי נשארת למשתמש.

זמני השרת: hello חם 156ms, שינויי פריטים לרוב 146–393ms, העלאה חדשה 889ms. הזמן הכולל בסביבת הבדיקה היה כ-5–8 שניות. **זו אינה מדידה מהטלפון ואינה הבטחה למהירות אצל המשתמש.** הפירוט ב-findings.md.

1. **לאחר בדיקת הפרשים, סנכרון ומעבר מאושר: בדיקה בטלפון בקישור האישי הקיים** (אפשר לקחת test_link מהגיליון הישן ולהוסיף `&debug=1`): פתיחה, צילום, גלריה/PDF, לא היה לי וביטול, הערה, מסך תודה וניסיון חוזר אחרי ניתוק. לציין Wi-Fi או סלולרי. הרשימה המלאה ב-status-5-2.md. בקשת המאפייה כבר complete, לכן לבדיקת מעבר ראשון למסך תודה יש לבחור לקוח אחר שטרם השלים.
2. **לפריסות עתידיות באמצעות GitHub Actions:** להגדיר בסודות המאגר `SUPABASE_ACCESS_TOKEN` ו-`SUPABASE_DB_PASSWORD`, ואז להריץ Deploy Supabase ב-main. הסודות לא היו זמינים לעוזר. הפריסה הראשונית ל-Supabase כבר בוצעה דרך החיבור; ההיעדר אינו חוסם את הגרסה הנוכחית.
3. **שלב 6:** לוח הבקרה עם התחברות והרשאות משרד, כולל פתיחת מסמכים משני סוגי האחסון. עדיין לא נבנה ואין ממשק ניהול חלופי לגיליון בשלב הזה.
4. **שלב 7:** ספק דואר, שעות שקט, תזמון ומצב הדגמה מתקדם. אין שליחת מייל או טריגרים פעילים חדשים.
