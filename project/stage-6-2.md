# Nelio — שלב 6.2: תיק לקוח ומסמכים

## מימוש
- רשימת לקוחות עם חיפוש, סינון עובד/מצב/תדירות, ובחירת מחזור.
- תיק לקוח לקריאה בלבד, פריטי מסמך ומצב, הערות וקבצים.
- `nelio-office` בודקת JWT מול Supabase Auth והרשאת משרד בכל קריאה; קריאה לפי מזהה בקשה מאומתת בשרת. מפתחות שירות אינם נשלחים לדפדפן.
- קובץ Supabase: signed URL ל־60 שניות רק לאחר בדיקת `ready` ושיוך לבקשה.
- קובץ Drive: השרת מקבל OAuth service-account token ב־JWT שנחתם בשרת, מוריד את תוכן הקובץ ומחזיר אותו רק למשתמש משרד מורשה. אין קישור Drive ציבורי או מפתח בדפדפן.

## הפעלת ארכיון Drive — נדרש אישור חשבון המשרד
1. בפרויקט Google Cloud של המשרד יש להפעיל את Google Drive API וליצור **Service Account** ייעודי לקריאה בלבד. לא לפתוח פרויקט בתשלום.
2. להעניק לכתובת ה־Service Account הרשאת **Viewer** לתיקיית שורש הארכיון ב־Drive (ולוודא שלקבצים הקיימים יש הרשאה בפועל). לא לבחור Anyone with the link.
3. להפיק JSON key לפי מדיניות האבטחה, ולהגדיר את תוכנו **רק** כסוד Edge Function בשם `NELIO_DRIVE_SERVICE_ACCOUNT_JSON` ב־Supabase. אין לפרסם את JSON או לשלוח אותו בצ'אט או ל־GitHub. רצוי להשתמש באמצעי סודי מאובטח, ולמחוק הורדות זמניות.
4. לפרוס מחדש את `nelio-office` ולבדוק קובץ היסטורי אמיתי מנתוני הדמה.
5. בהיעדר הגדרה השרת מחזיר `DRIVE_NOT_CONFIGURED`; אין נפילה לנתיב ציבורי.
