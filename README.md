# Nelio

מערכת לאיסוף מסמכים חודשי למשרד רואי חשבון. כל לקוח מקבל קישור אישי ומעלה מהטלפון, הקבצים נשמרים לבד בתיקייה הנכונה, והמשרד רואה במסך אחד מה חסר.

**פרויקט הדגמה.** המשרד, "שדמי ושות', רואי חשבון", בדיוני, וכל הנתונים במערכת מומצאים.

## מה יש כאן

| תיקייה | מה יש בה |
|---|---|
| `docs/` | הדף של הלקוח. GitHub Pages מפרסם אותו בכתובת https://shedmi-cpa.github.io/nelio/ |
| `supabase/` | השרת החדש, סכמת PostgreSQL, בדיקות והוראות פריסה |
| `apps-script/` | השרת הקודם, שמור לצורכי תיעוד וחזרה מבוקרת |
| `demo/` | המחולל של משרד הדמו: 60 לקוחות בדויים, שני חודשים סגורים וחודש פתוח (`seed.json`) |
| `.github/workflows/` | בדיקות אוטומטיות ופריסות שרת ידניות |

## איך זה עובד

בגרסת המעבר שבענף זה הדף פונה לשרת ב-Supabase. האתר הציבורי עדיין פונה ל-Apps Script עד מיזוג מאושר לאחר בדיקת הפרשים וסנכרון. הנתונים נשמרים ב-PostgreSQL, והעלאות חדשות באחסון פרטי. המסמכים הישנים נשארו ב-Drive והקישורים האישיים ממשיכים לעבוד.

## פריסה ובדיקות

הוראות מלאות נמצאות ב-[supabase/README.md](supabase/README.md). הדף מתפרסם מ-`docs/` באמצעות GitHub Pages. השרת החדש נפרס ב-Supabase; הוכן תהליך GitHub Actions לפריסות הבאות, שדורש הגדרת שני סודות. הבדיקות המקומיות רצות אוטומטית ב-PR וב-main.

## מצב

גרסה 0.6.0: מעבר צד השרת ומסד הנתונים ל-Supabase. הפריסה הראשונית של השרת בוצעה; PR המעבר נועד להישאר פתוח עד לבדיקת שינויים בגיליון מאז ההעתקה ולסנכרון לפי הצורך; אין להפעיל auto-merge. שלב 5 עדיין ממתין לבדיקה בטלפון. לוח הבקרה ושליחת דואר מתוזמנת הם השלבים הבאים.
